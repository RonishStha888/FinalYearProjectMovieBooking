Abstract
Soluna is a digital mental wellness system which helps people manage their emotions through integrated self-help tools. The application solves worldwide mental health problems through its straightforward system which unites mood tracking with affirmations, reflective journaling, chatbot assistance, self-care resources and progress monitoring into one platform. Soluna provides an all-in-one solution which unites preventive care with resilience development and long-term self-care maintenance in contrast to current systems that separate these elements. The modern technology stack of React, Node.js, MySQL and supportive libraries helps in Soluna's user-centered design, real-time data visualization and personalized guidance features. The project uses Kanban methodology to create an adaptable development process which allows for ongoing enhancements through feedback loops. Soluna provides immediate help to people while teaching them to understand themselves better and build emotional strength.

1.	Introduction
1.1.	Purpose
This SRS document specifies the functional, non-functional, and usability requirements for Soluna, a web-based mental health wellness platform. Soluna combines mood tracking, affirmations, journaling, chatbot support, self-care libraries, and reporting of users' progress and managing their emotional well-being. The organization of this SRS is done according to the subsystems as shown in the Functional Decomposition Diagram (FDD). The Agile Kanban approach is followed for development, which allows for a continuous workflow, incremental delivery, and iterative enhancement by dealing with one subsystem at a time.

1.2.	Subsystems
Soluna includes the following subsystems:
1.2.1.	User Management System
It is in charge of the secure authentication as well as user registration, login, logout, and profile management.
1.2.2.	Mood Tracking and Affirmation
This subsystem allows users to log the mood on a daily basis, receive mood-based affirmations, and view the trends through charts and heatmaps.
1.2.3.	Journaling
It is possible for users to create, edit, delete, and search personal journal entries, while ensuring privacy. 
1.2.4.	Chatbot
It uses the third-party chatbot API for providing supportive and empathetic conversations.
1.2.5.	Self-Care Library
The library includes self-care activities guided by breathing exercises, meditation, calming sounds, and art therapy.
1.2.6.	Progress Report
It creates weekly and monthly reports that include mood, journaling, and self-care usage data.
1.2.7.	Admin Panel
It is a platform for the administrators to control user access, watch over the system usage, add self-care content, and ensure the platform is secure.

2.	Overall Description
2.1.	Product Perspective
Soluna is a digital mental wellness platform addressing global mental health challenges, integrating mood tracking, affirmations, journaling, chatbot support, self-care resources, and progress monitoring in one app. Unlike single-purpose apps, it promotes preventive care and long-term resilience, built with React, Node.js, MySQL, and managed via Kanban for flexible development.

2.2.	Product Functions
•	Users register/login, track moods with affirmations, journal reflections, chat with AI for guidance, access self-care resources, and view progress reports.
•	Admins manage users (suspend/unban) and content (add/edit self-care resources).
•	System ensures secure data handling and real-time visualizations.

2.3.	Stakeholders
•	End Users: End users are people who register and log in to use Soluna.
•	Admin: Admin refers to administrators who manage users, content, and system security.
•	Guests: Guests are visitors who do not log in.

2.4.	Operating Environment
•	Frontend: React.js, works on modern browsers.
•	Backend: Node.js with Express.
•	Database: MySQL for storing data.
•	Third-Party: Ollama AI (chatbot), Chart.js (visuals), Quill (journal), etc.
•	Network: Internet required; HTTPS-secured.

2.5.	Design and Implementation
•	Use Kanban methodology for development.
•	Ensure data privacy and user consent.
•	Chatbot is supportive only, not therapy.
•	Web-based only; no native mobile app.

2.6.	Assumptions and Dependencies
•	Users have stable internet access for real-time features.
•	Third-party APIs (e.g., Ollama, Google OAuth) are available and stable.
•	Database handles relational data efficiently.
•	No integration with external medical systems.
